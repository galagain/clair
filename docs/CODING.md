# Coding + Firefox

1. Dans **Clair → bouton ⌄ à côté de Code → Réglages Coding → Firefox**, clique sur **Ouvrir l’extension**.
2. Dans Firefox 140 ou plus récent, ouvre `about:debugging#/runtime/this-firefox`, clique sur **Charger un module complémentaire temporaire**, puis choisis `manifest.json` dans ce dossier. Le ZIP `Clair-Firefox.zip` convient aussi.
3. Dans Clair, clique sur **Copier le code**. Ouvre l’extension, colle-le dans **Connexion à Clair**, puis clique sur **Connecter**. Ce code relie les deux applications ; ce n’est pas ta clé API.
4. Sur la page d’exercice, presse **Alt ⇧ C** : l’extension envoie la page entière accessible, le code accessible et les sorties de tests à Clair, qui affiche la solution. Aucun popup Firefox ne s’ouvre. Une ancienne sélection de texte ne limite plus le raccourci. Pour envoyer seulement une sélection, contrôler ou modifier le contenu avant l’envoi, clique plutôt sur l’icône de l’extension et utilise **Envoyer et analyser**.

Le raccourci fonctionne lorsque Firefox a le focus. Trois commandes supplémentaires permettent d’ajouter d’autres raccourcis. Elles se configurent dans `about:addons` → roue dentée → **Gérer les raccourcis des extensions**. En cas d’échec, un **!** apparaît sur l’icône ; le détail est accessible en ouvrant l’extension. Aucune notification système ni fenêtre ne s’ouvre automatiquement. Le raccourci ne rend pas Clair invisible dans un partage d’écran.

L’onglet **Coding** affiche la solution avec quelques commentaires courts en français pour comprendre les étapes. Dans **Pistes**, « Repères du code » résume l’approche, les étapes essentielles, la complexité et les cas limites pertinents, dans la langue choisie pour les pistes. Ces repères décrivent le code affiché ; les réponses d’entretien et leur historique restent disponibles. Un repère « Reçu » avec l’heure et le site, en haut du Code, confirme chaque nouvel envoi. Une lecture de page bloquée expire après dix secondes : le prochain raccourci reste utilisable, sans envoi tardif automatique. Chaque raccourci remplace la précédente et annule sa génération si elle est encore en cours. Les réglages et commandes sont dans **bouton ⌄ à côté de Code → Réglages Coding**, en haut de Clair. **Résoudre** utilise le contenu envoyé ou modifié dans Clair. **Copier** copie la solution avec son indentation. **Effacer** retire l’exercice et la solution ; l’export de session inclut seulement la solution actuelle.

Les Pistes orales reçoivent l’énoncé et la dernière solution complète affichée. Un nouvel exercice réinitialise le contexte de génération des pistes pour éviter de mélanger les exercices ; le fil déjà affiché reste disponible. Effacer Code retire ce contexte.

L’aide utilise le modèle et la clé déjà configurés dans Clair. Python et C++ sont sélectionnables. Si une information indispensable manque, une courte question remplace le code. Le micro n’est pas nécessaire pour résoudre un exercice ; il sert au suivi vocal décrit ci-dessous.

## Consignes en image ou en plusieurs zones

Dans **menu Coding → Capture Firefox**, choisis **Page complète — texte + images**, puis utilise le même raccourci ou bouton de souris. Clair reçoit le texte de la page, le code accessible et des captures de l’onglet Firefox, y compris les schémas, images et formules rendus. **Texte** reste le mode par défaut. Le réglage s’applique au prochain envoi ; recharge l’extension mise à jour pour disposer de ce mode.

La page est capturée par tranches, sans défilement ni déplacement du pointeur. La capture couvre jusqu’à 2 400 pixels CSS de largeur et 8 400 de hauteur, en six images maximum, avec une limite totale de 8 millions de caractères encodés. Un avertissement signale une page tronquée ; pour une consigne dans une zone à défilement interne ou chargée à la demande, rends cette zone visible avant de renvoyer. Si le texte est inaccessible, une capture de la zone visible sert de secours. Aucun envoi texte seul ne remplace silencieusement un échec du mode image.

Il s’agit de la page Firefox, sans les autres fenêtres du bureau. Le HTML brut n’est pas envoyé : il ne contient pas les pixels des images. Les images sont transmises au modèle avec la demande, puis conservées seulement en mémoire pour la réanalyse, le suivi vocal facultatif et les repères. Elles disparaissent au remplacement de l’exercice, à Effacer ou à la fermeture. Les requêtes contenant ces images peuvent consommer davantage de jetons. Les pistes orales ordinaires reçoivent le texte et le code sans recopier les données image dans leur JSON.

## Réanalyser les échanges récents

Le petit bouton **↻ en haut à droite du rectangle Code** relance l’analyse avec la dernière capture Firefox, la solution actuelle et les **deux dernières minutes de transcription finalisée**, jusqu’à 6 000 caractères. Le contexte inclut le micro et le son de l’ordinateur, avec leurs sources lorsqu’elles sont connues. L’écoute doit avoir produit au moins une phrase récente ; sinon un message invite à démarrer l’écoute. Le bouton fonctionne aussi après avoir arrêté l’écoute tant que les phrases sont encore récentes.

L’ancien code reste visible pendant la réanalyse ; une réponse complète le remplace et **Revenir** permet d’annuler ce changement. Si le code convient déjà, il est conservé. Les repères de Pistes sont régénérés après une solution ou une réanalyse manuelle. Le bouton n’effectue pas une nouvelle capture de CoderPad : pour tenir compte des modifications dans l’éditeur du navigateur, renvoie d’abord la page avec Alt ⇧ C.

Les repères utilisent un appel API supplémentaire après la génération du code ; leur échec ne supprime pas le code. La réanalyse manuelle utilise aussi le compte API configuré. Tout reste en mémoire jusqu’à la fermeture ou à l’effacement de la session. Les repères apparaissent également dans Pistes sur l’iPhone, qui reste un écran de lecture.

## Suivre ma voix

**Suivre ma voix**, dans le menu Coding, est désactivé par défaut. Active-le uniquement si tu veux que les paroles modifient le code. Envoie d’abord un exercice et démarre l’écoute. Choisis dans **Discours original** la langue dans laquelle tu parles. Après une pause d’environ 1,5 seconde dans la transcription, les dernières paroles attribuées au **microphone** peuvent adapter la solution actuelle : par exemple « utilisons un dictionnaire à la place » ou « traitons aussi le tableau vide ». Le modèle doit garder le code si tu expliques simplement la solution, si le changement est déjà présent ou si la demande est ambiguë. Les changements sont limités au nécessaire, avec de courts commentaires en français.

L’ancienne solution reste affichée pendant la génération. Une adaptation complète la remplace d’un coup, sur Mac et iPhone, en conservant la position de lecture sur Mac. **Revenir** annule la dernière adaptation ; un nouvel exercice efface ce retour possible. Une erreur, un refus, une réponse interrompue ou un arrêt conserve le code précédent. **Arrêter** annule la génération en cours ; décoche **Suivre ma voix** pour empêcher les suivantes. L’arrêt de l’écoute, la veille et la fermeture annulent aussi les adaptations.

Les phrases finalisées sont regroupées et deux analyses sont espacées d’au moins huit secondes, sans arrêter l’écoute. Elles utilisent la clé et le modèle déjà configurés et **consomment des appels API supplémentaires**, même si le modèle décide de conserver le code. Le code courant et jusqu’à 6 000 caractères de paroles récentes sont transmis à OpenAI. Aucune modification n’est écrite dans Firefox ou CoderPad.

L’attribution micro/son système repose sur les niveaux audio, pas sur une identification certaine du locuteur. Les sources ambiguës et le son système sont exclus du suivi ; la transcription peut encore mal comprendre un accent ou un mot. La pertinence des adaptations réelles reste à vérifier avec ta voix et ton exercice.

## Limites

- L’extension est **non signée** : il faut la recharger après chaque fermeture de Firefox. Une distribution permanente nécessite une signature Mozilla. La fermer ne révoque pas le code de connexion ; **Déconnecter** dans Clair le révoque. Un redémarrage de Clair exige une nouvelle connexion.
- Les éditeurs Monaco, CodeMirror et Ace exposant leur modèle peuvent fournir le code complet. Sinon, seule la partie rendue est accessible. Un avertissement accompagne alors la capture dans Clair. Si plusieurs éditeurs sont détectés, le raccourci ne choisit pas de code au hasard : sélectionne le bon éditeur dans l’aperçu manuel ou colle ton code dans Clair. Les cadres d’une autre origine peuvent être inaccessibles. Aucune compatibilité avec une session CoderPad réelle n’est garantie sans essai.
- Aucun code n’est exécuté, aucun texte n’est écrit dans l’éditeur et aucune soumission n’est faite.
- Le contenu n’est pas rafraîchi en continu : un raccourci envoie une nouvelle capture, un clic envoie l’aperçu modifié. Aucun nouvel envoi automatique après une erreur. Les bornes sont 24 000 caractères d’énoncé, 32 000 de code et 8 000 de sorties de tests. La solution actuelle et la version précédant sa dernière adaptation vocale sont conservées pendant cette session.

## Données

L’accès est limité à l’onglet activé par l’utilisateur et à une connexion locale sur `127.0.0.1`. Le serveur local démarre au clic sur **Copier le code** et exige un code aléatoire. L’extension ne reçoit jamais la clé OpenAI. Elle conserve le code de connexion et le langage de code choisi dans son stockage local, ainsi que le dernier statut du raccourci pendant la session Firefox ; l’aperçu disparaît à sa fermeture.

Le texte sélectionné ou rendu de la page, le code et les sorties visibles sont transmis au raccourci, sans aperçu préalable. L’icône permet toujours de consulter l’aperçu manuel. Le mode Texte n’envoie pas de HTML brut, de cookies, d’historique de navigation ni de valeurs de formulaire extraites. En mode texte + images, tout contenu rendu dans la zone capturée peut apparaître dans les images de la page. Le titre et le nom d’hôte de la page accompagnent l’exercice ; son URL complète n’est pas envoyée. Du texte sensible affiché dans la page peut figurer dans la capture : utilise le raccourci sur l’exercice voulu.

**Alt ⇧ C** ou **Envoyer et analyser** transmet ces données à Clair puis à OpenAI, avec `store:false`, sur le compte API configuré. Si **Suivre ma voix** est actif pendant l’écoute, les adaptations décrites ci-dessus provoquent aussi des envois automatiques. Clair garde l’exercice et sa solution en mémoire jusqu’au prochain envoi, à leur effacement ou à sa fermeture. L’export manuel écrit la solution actuelle sur disque. Utilise ce mode pour tes entraînements ou les sessions où l’assistance est autorisée.
